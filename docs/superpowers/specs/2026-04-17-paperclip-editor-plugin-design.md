# Paperclip Editor Plugin Design

## Summary

Build a new Paperclip plugin under `paperclip-editor-plugin` that exposes an issue-scoped `Open in...` split button. The UI stays hidden unless the browser host is `localhost` and the worker can resolve a local workspace path for the current issue.

## Architecture

- `src/manifest.ts` declares a single issue `toolbarButton` slot and the minimal capabilities required to read issues and project workspaces.
- `src/worker.ts` exposes:
  - `editor.availability` for UI visibility and menu contents
  - `editor.launch` for the curated IntelliJ launcher action
- `src/ui/index.tsx` renders the split button and dropdown, hides itself when the action is unavailable, and launches IntelliJ through the worker.

## Safety

- Resolve workspaces through `ctx.issues.get(...)` and `ctx.projects.listWorkspaces(...)`.
- Trust only `localhost` and `127.0.0.1` for visibility and launch eligibility.
- Launch only curated commands generated by the worker, never raw UI input.
